SDD Framework

Contratos, documentación y herramientas para organizar el trabajo de personas y agentes. Define cómo avanza una funcionalidad y qué debe comprobarse en cada etapa.

Repositorio públicoApache-2.0
Ver el repositorio en GitHub →Leer la documentación

Qué aporta

Reglas que se pueden leer.
Contratos que se pueden validar.

El framework combina documentos de trabajo con reglas legibles por máquina. Se instala dentro de un repositorio existente bajo docs/sdd/; el código del producto permanece fuera de ese árbol.

01 · Contratos

Esquema y protocolo.

El esquema define la forma y las invariantes del registro de funcionalidad. El protocolo define las transiciones, gates, bloqueos y regresiones del ciclo SDD.

Estado y siguientes rutas.

Las consultas status y next permiten inspeccionar un registro y los gates declarados por el protocolo. Son de solo lectura: no avanzan el ciclo ni ejecutan trabajo ni modifican el registro.

Alcance de instalación.

El instalador actual requiere Python 3.11 o posterior y un repositorio existente sin instalación previa en docs/sdd/. Permite examinar los destinos con --dry-run y rechaza sobrescribir una instalación existente.

La documentación del repositorio detalla los requisitos y las comprobaciones de instalación.

Alcance de las reglas.

Validar un registro confirma las reglas que cubre el contrato. No demuestra por sí solo el efecto de una operación sobre otro sistema, ni concede permiso para hacer push, merge o desplegar.

Los permisos técnicos y la comprobación del efecto corresponden al dominio que realiza la operación.

SDD y RepoOps

El trabajo tiene criterios.
La operación tiene condiciones.

SDD es la ruta funcional inicial del nuevo RepoOps. El cliente prepara material y revisiones; el motor comprueba las condiciones de la operación y gobierna el efecto Git admitido.

El registro de funcionalidad pertenece al contrato del framework. Su existencia no fija la autoridad de estado ni la representación del motor sucesor: esos detalles siguen en definición.
